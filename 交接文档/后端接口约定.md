# 后端接口约定

以下是推荐的最小接口，可根据后端技术栈调整。

## 聊天

`POST /api/chat`

请求示例：

```json
{
  "sessionId": "demo-user",
  "message": "请提醒我晚上八点吃药"
}
```

响应示例：

```json
{
  "summary": "好的，我可以帮您设置提醒。",
  "detail": "请确认药物名称和提醒时间。",
  "needConfirmation": true,
  "action": {
    "type": "create_reminder",
    "draft": {
      "content": "服药",
      "time": "20:00"
    }
  }
}
```

## 备忘

以下接口均使用登录凭证。搜索在前端完成。创建时提交 id、created、fields，重复提交相同 id 会返回当前记录。编辑时提交 revision 和 fields。fields 包含 text、when、details、scheduleAnchor。若编辑期间记录已在别处更新，服务返回 409。

- `GET /api/memos`
- `POST /api/memos`
- `PUT /api/memos/{id}`
- `DELETE /api/memos/{id}?revision=当前版本`

只有用户明确确认后才能新增或修改备忘。

## 提醒

- `GET /api/reminders`
- `POST /api/reminders`
- `PATCH /api/reminders/{id}`
- `DELETE /api/reminders/{id}`

推荐字段：

```json
{
  "content": "服用晚间药物",
  "remindAt": "2026-12-24T20:00:00+08:00",
  "timezone": "Asia/Shanghai",
  "enabled": true
}
```

## 前端接入原则

- 前端只调用自己的后端，不直接调用大模型服务。
- 所有新增、编辑和删除操作都应处理失败状态。
- 接口返回给老年用户的错误提示要简短、明确，并提供重试入口。
- 网络超时后不要重复创建提醒，后端应支持幂等请求。
